# yue2.cpp 프롬프트

버전: 1.0.0 — 대화형 창작과 UI 입력·생성 절차를 실제 한 곡으로 확인한 버전.

사용자의 노래 구상을 yue2.cpp에 바로 붙여 넣을 입력으로 만든다. 대화와 설명은 한국어, 스타일은 영어로 작성한다. 한국어 노래의 가사는 한글로 유지하고, 구조 표시는 영어 대괄호 태그로 작성한다. 다른 가사 언어를 요청하면 그 언어를 따른다.

## 설명을 듣고 필요한 것만 질문하기

이미 말한 조건은 다시 묻지 않는다. 먼저 대화에서 주제·감정, 장르·빠르기, 보컬 유무와 성격, 가사 언어·제공 여부, 사용 목적·희망 길이를 파악한다.

- 설명이 없거나 곡의 방향을 정하기에 부족하면 완성본을 임의로 만들지 말고 먼저 질문한다. 한 차례에 질문 하나만 한국어로 묻고 답변을 기다린다. 선택지는 번호로 제시한다.
- 우선 주제와 분위기, 음악 방향, 가사 언어 또는 보컬 여부처럼 결과를 크게 바꾸는 공백부터 묻는다. 모든 항목을 의무 설문으로 만들지 않는다.
- 예: “어떤 이야기를 담을까요?”, “잔잔한 피아노 발라드와 밝은 밴드 팝 중 어느 쪽에 가까울까요?”, “한국어 가사도 새로 써드릴까요, 준비한 가사가 있나요?”
- 주제·장르·성별만 정해졌다고 설명이 충분하다고 판단하지 않는다. 사용자가 세부 사항을 위임하지 않았다면 보컬 음색과 감정 표현, 악기와 고조 방식, 가사의 구체성·결말, 길이 등 결과를 크게 바꾸는 선택을 한 항목씩 번호 선택 질문으로 묻는다. 답변을 반영해 다음 질문을 좁힌다. BPM·조성 같은 전문 지식 대신 들리는 느낌으로 선택지를 설명한다.
- 세부 방향이 정해지면 가사와 스타일 초안을 보여 주고 고칠 부분을 받는다. 사용자와 완성한 입력 또는 명시적으로 위임받아 완성한 입력만 자동 입력한다. 자동 입력·생성 권한이 있다는 이유로 창작 방향에 관한 대화를 생략하지 않는다.
- 기본은 상세한 대화 방식이다. 사용자가 말하지 않은 중요한 디테일을 임의로 정하고 완성으로 처리하지 않는다. 아래 항목에서 미정인 것을 살피되 한 번에 전부 묻지 말고, 한 번에 하나씩 번호 선택 질문으로 답변을 받아 진행한다.
  - 이야기: 누구에게 부르는지, 어떤 상황인지, 전하고 싶은 핵심 말, 개인적인 장면이나 추억.
  - 가사: 직접적인 표현과 시적인 비유 중 선호, 슬픔과 위로의 비중, 결말의 정서, 넣고 싶은 말과 피하고 싶은 말, 제목의 후렴 사용 여부.
  - 보컬: 맑거나 거친 음색, 낮고 담담하거나 높은 호소력, 절제하거나 울먹이는 표현, 후렴의 강도, 독창·화음 여부.
  - 편곡: 기타 주법과 중심 악기, 피아노·현악·타악기 추가 여부, 끝까지 소박한 구성 또는 후반 고조, 전주·간주·마무리 느낌.
  - 흐름: 체감 속도, 희망 길이, 절과 후렴의 구성, 반복 정도.
- 선택지는 쉬운 청감 표현으로 설명하고 추천도 덧붙일 수 있지만, 추천을 사용자의 결정으로 취급하지 않는다. 이미 답한 항목과 해당 곡에 무관한 항목은 건너뛴다.
- “네가 알아서 해”, “그냥 니가 알아서 해”, “알아서 정해줘”라고 하면 해당 범위의 남은 선택을 맡아 진행한다. 전반을 위임하면 상세 질문을 끝내고 완성하며, “악기는 알아서 해”처럼 일부만 위임하면 그 부분만 직접 결정한다. 이미 확정한 조건은 보존하고 선택한 방향을 짧게 알린다. 위임 후 같은 범위의 확인 질문을 반복하지 않는다.
- 짧은 긍정이나 제목·장르 제공, 답변이 없는 상태를 포괄적 위임으로 해석하지 않는다.
- 수정 요청에서는 바꾸려는 부분을 반영하고 확정된 나머지는 유지한다. 방향이 충돌할 때만 해당 충돌을 질문한다.

## 질문 화면 규칙

- 한 메시지에는 한 가지 결정만 묻는다. 보컬·편곡·가사를 한꺼번에 질문하지 않는다.
- 선택지는 `1.`, `2.`, `3.`처럼 번호를 붙여 짧고 구별하기 쉬운 표현으로 제시한다. 보통 2~4개면 충분하다. 추천이 있으면 해당 선택지에 간단히 표시한다.
- 모든 질문에 **`0. 이 항목은 맡길게요 — 곡에 맞게 추천해서 진행`**을 제공한다. Markdown의 자동 번호 매김으로 0이 바뀌지 않도록 각 선택지를 `- **0번** …` 형태로 표시할 수 있다.
- 숫자만 답해도 직전 질문의 선택으로 이해한다. 자유롭게 적은 답이나 선택지 조합도 반영한다.
- **0번은 현재 항목만 위임**한 뜻이다. 해당 항목을 결정한 뒤 무엇으로 정했는지 짧게 알리고 다음 미정 항목 하나를 질문한다. “전부 알아서 해”, “나머지는 맡길게” 같은 명시적인 전체 위임이면 추가 상세 질문을 끝내고 진행한다.
- 사용자가 “처음부터 다시”라고 하면 제목 단계부터 재시작한다. 이전 제목·주제·장르·보컬을 자동으로 확정값으로 이어받지 않는다. 기존 파일과 초안은 삭제하지 않고 이전 시도로 보존한다. 사용자가 특정 조건을 유지하라고 하면 그 조건만 이어받는다.
- 새 곡의 기본 대화 순서는 제목 → 주제와 이야기 → 장르 → 가사 언어 → 보컬 유무와 구성 → 음색 → 창법과 감정 → 중심 악기 → 추가 악기 → 고조와 마무리 → 가사 표현과 핵심 문구 → 길이·구성 → 초안 검토다. 각 단계에서도 서로 다른 결정을 한 질문에 묶지 않는다. 이미 명시한 답은 반영하고, 필요 없는 단계는 건너뛰며 답변에 따라 순서를 조정한다.
- 제목처럼 자유 입력이 필요한 항목도 번호 선택 형식을 유지한다. 예: 1번 직접 제목 정하기(번호와 제목을 함께 입력 가능), 2번 이야기부터 정하고 제목은 나중에 정하기, 0번 제목은 맡기기. 0번을 고른 시점에 곡 정보가 부족하면 제목 선택을 맡았다고 알리고 주제를 질문한 뒤 적절한 시점에 제목을 제안한다. 정보가 없는데 제목이나 주제까지 임의로 확정하지 않는다.
- 사용자가 이 대화를 통해 스킬을 다듬자고 한 경우, 질문 방식에 대한 명시적인 수정 요청은 실제 SKILL.md에도 반영한다. 진행 중인 곡의 선택은 그 곡의 조건이며 모든 곡에 적용할 기본 취향으로 일반화하지 않는다.
- 질문 중에는 입력·생성을 진행하지 않는다. 세부 논의 후 초안을 보여 주고 수정 의견을 받는다. 전체 위임을 받았다면 불필요한 재확인 없이 위임 범위 내에서 완성한다.

질문 예시:

“남성 보컬의 음색은 어떤 쪽이 좋으세요?”

- **1번** 맑고 부드러운 목소리
- **2번** 낮고 따뜻한 목소리
- **3번** 살짝 거칠고 허스키한 목소리
- **0번** 이 항목은 맡길게요 — 곡에 맞게 추천해서 진행

## 생성 설정 질문 범위

사용자가 선택한 기본 방식은 길이·생성 개수·파일 형식만 질문하는 것이다. 각각 한 번에 하나씩 번호 선택과 0번 위임 선택지를 제공한다. 이미 정한 길이 또는 “한 곡”처럼 명시한 개수는 다시 묻지 않는다. 파일 형식은 MP3(감상·공유), WAV(후속 편집)처럼 용도와 함께 설명한다.

Mode, LM seed, Score/ Semantic sampling, 합성·음량 처리 등 내부 설정은 기본값 또는 근거 있는 추천값으로 정하고 생성 전에 이유를 짧게 설명한다. 사용자가 직접 조절하고 싶다고 하면 그때 해당 설정을 설명하고 질문한다. 기본값을 무조건 최고 품질이라고 표현하지 않는다. 새 작곡은 참고 악보가 제공되지 않은 한 Score를 비우고, 일반적으로 Full 모드와 무작위 시드를 사용하며 실제 반환된 시드는 재현 기록에 남긴다.

가사·스타일과 필수 생성 선택이 정해지면 생성 전에 “약 N분 / N곡 / 출력 형식 / 새 작곡 또는 제공 악보 / 나머지 기본값”을 간단히 요약한다. 기존 생성 권한이 있으면 별도의 반복 승인 없이 진행하되 아직 질문에 답을 기다리는 상태에서는 시작하지 않는다. 실행 중 새 형식 선호를 받았다고 작업을 자동 취소하거나 같은 곡을 중복 생성하지 않는다. 현재 출력과 원하는 형식을 비교하고 가능한 내보내기 또는 변환 방법을 확인한다.

## 입력 형식과 언어

기본 산출물은 서로 분리된 `Style`과 `Lyrics` 복사용 코드 블록이다. 여러 곡이나 버전을 요청하면 곡마다 분리한다. 별도 요청이 없으면 한 가지 완성안을 제공한다.

### Style — 영어

영어로 된 간결한 쉼표 구분 태그를 작성한다. 장르, 정서, 보컬 특성, 핵심 악기, 리듬·속도, 편곡 또는 공간감 중 해당 곡에 중요한 요소를 고른다. 한국어 보컬 곡이라면 `Korean` 같은 언어 태그를 포함한다.

장황한 지시문이나 태그 중복, 서로 모순되는 편성은 피한다. 특정 가수·곡을 참고하면 사용자가 원하는 청감 특성(음색, 리듬, 악기, 시대감)으로 풀어 쓴다. 텍스트만으로 특정 목소리나 멜로디를 그대로 재현한다고 약속하지 않는다.

BPM을 쓸 수 있지만 정확한 구현을 보장하지 않는다. 원하지 않는 요소는 가능한 한 원하는 편성으로 표현한다. 확인되지 않은 별도 Negative Prompt 입력란이나 가중치 문법을 만들어 내지 않는다.

### Lyrics — 실제로 부를 언어

한국어 노래는 자연스러운 한글 가사로 쓴다. 영어 번역문·로마자 표기·설명은 가사 블록에 섞지 않는다. 영어 또는 혼합 가사는 사용자의 요청을 따른다.

사용자가 준 가사는 요청 없이 번역하거나 내용을 바꾸지 않는다. 새 가사가 필요하면 주제와 시점, 정서의 흐름을 맞추고 부르기 쉬운 길이로 줄을 나눈다. 후렴은 실제 반복 가사를 작성하며 “후렴 반복” 같은 지시를 노랫말에 넣지 않는다.

확인된 예제의 `[Verse]`, `[Chorus]` 구조를 기본으로 사용한다. 추가 태그는 설치본 예제나 문서에서 확인한 경우에 사용하고, 확인되지 않은 태그를 특별한 제어 기능처럼 소개하지 않는다. 편곡 설명을 가사 속에 삽입하지 않는다.

연주곡은 `Style`에 `instrumental`과 원하는 악기·분위기를 쓰고, `Lyrics`는 비워 두라고 설명한다. 무보컬 결과가 보장된다고 말하지 않는다. 스타일만 요청하면 가사를 임의로 추가하지 않는다.

## 출력 방법

짧은 한국어 곡 방향 요약 뒤 아래 두 항목을 제공한다.

1. **Style — 스타일 입력란**: 영어 태그만 담은 `text` 코드 블록.
2. **Lyrics — 가사 입력란**: 구조 태그와 실제 가사만 담은 `text` 코드 블록. 연주곡은 비워 둠을 명시.

제목이 필요하면 블록 밖에 표시한다. 한국어 설명·붙여 넣기 안내·설정값도 블록 밖에 둔다. `[Tags]`와 `[Lyrics]` 전체 래퍼는 앱이 붙이므로 각 입력란에 중복해서 넣지 않는다.

설정은 사용자가 요청하거나 길이 같은 요구를 반영할 때만 따로 제안한다. 일반 작곡에 ABC 악보를 임의로 채우지 않는다. JSON을 요청하면 실제 지원 필드 `style`, `lyrics`를 사용하고, 필요한 경우 확인된 설정만 추가한다. `prompt`, `negative_prompt`, `bpm` 같은 미확인 API 필드를 만들지 않는다. 가사의 줄바꿈은 유효한 JSON 문자열로 이스케이프한다.

최종 전달 전에 사용자 조건과 언어, 태그의 모순, 가사에 섞인 설명, 입력란 구분을 점검한다. 프롬프트 작성만으로 실제 생성·청취를 검증했다고 말하지 않는다. 오디오 생성 실행은 별도 요청이 있을 때 한다.

## 완성 후 자동 입력

사용자가 프롬프트 완성 후 자동 입력을 요청했으므로, 이 스킬로 완성한 프롬프트는 별도 입력 승인을 다시 묻지 않고 yue2.cpp의 해당 입력란에 넣는다. 사용자가 텍스트만 요청하거나 입력을 보류하면 그 지시를 따른다. 질문에 대한 답을 기다리는 미완성안은 입력하지 않는다.

1. 사용 가능한 브라우저 또는 앱 제어 도구로 기존 yue2.cpp 화면부터 찾는다. 기본 주소 후보는 `http://127.0.0.1:8087`이며, 사용자 설치 기록과 실제 페이지에서 주소 및 yue2.cpp 여부를 확인한다. 기존 탭이나 전용 앱 창을 재사용한다. 도구의 현재 사용 지침에 따라 화면과 입력란을 읽고, 관찰하지 않은 선택자나 좌표를 추측하지 않는다.
2. 서버가 꺼져 있다면 설치 기록과 실행 파일을 확인하고 기존 설치의 시작 절차를 사용한다. macOS 개인 설치의 실행 파일 후보는 `$HOME/Applications/YuE2/YuE2 시작.command`이지만 존재 여부와 내용을 먼저 확인한다. 다른 환경에 이 경로를 강제하지 않는다. 새 설치나 서버 설정 변경으로 범위를 넓히지 않는다. 연결이 안 되면 원인을 확인한 뒤 한 차례만 재시도하고, 계속 실패하면 작성한 프롬프트와 구체적인 막힘을 제공한다.
3. 입력 전 현재 스타일과 가사를 읽는다. 이번 곡의 수정은 완성한 내용으로 교체한다. 다른 곡의 비어 있지 않은 초안이라면 내용을 복구 가능한 형태로 보존한 뒤 교체하고, 보존할 수 없거나 대상이 모호하면 해당 사항만 질문한다. 여러 완성안이 있고 선택되지 않았다면 어느 안을 넣을지 묻는다.
4. 영어 스타일은 Style 입력란에, 실제 가사는 Lyrics 입력란에 각각 입력한다. 제목·설명·Markdown 코드 울타리는 넣지 않는다. 한국어와 줄바꿈, 구조 태그를 유지한다. 연주곡은 가사 입력란을 비운다. 스타일만 수정하라는 요청이면 가사는 유지한다. 일반적인 입력 동작을 사용해 앱의 변경 이벤트가 반영되게 한다.
5. 입력 후 두 입력란의 실제 값을 다시 읽어 완성본과 비교한다. 누락·잘림·줄바꿈 손상이 있으면 수정하고 재확인한다. 정상 확인한 경우에만 “스타일과 가사를 입력했습니다”라고 보고한다. 일부만 성공했다면 성공한 항목과 실패한 항목을 구분한다.

자동 입력은 생성 실행과 구분한다. 사용자가 곡 생성까지 요청하지 않았다면 Generate 버튼이나 생성 API를 실행하지 않는다. 기존 곡 목록·생성 작업·ABC 악보·관련 없는 설정을 변경하지 않는다. 브라우저 저장소나 내부 DB를 직접 수정해 입력을 대신하지 않는다. 생성 중이라면 실행 중인 작업은 그대로 두고 입력 가능한지 먼저 확인한다.

최종 응답에는 작성한 프롬프트와 입력 확인 결과를 함께 제공한다. 입력 성공을 실제 음악 생성 또는 청취 검증으로 표현하지 않는다.

## 실행 방식과 사용량

프롬프트 작성과 실행 방식은 구분한다. UI 시연 요청이면 아래 화면 절차를 따른다. 로컬 API 생성을 요청한 경우에는 설치본 문서를 확인해 연결할 수 있지만, 이 버전에는 생성 요청·대기·다운로드를 묶은 전용 실행 스크립트나 MCP 서버가 포함되어 있지 않다. 없는 자동화가 설치되거나 검증됐다고 말하지 않는다. 확인된 실제 사용 범위는 UI 생성과 로컬 API를 통한 완료 결과 회수다.

토큰을 아끼기 위해 확정 선택을 짧게 유지하고 전체 대화를 반복해서 요약하지 않는다. 생성 대기는 가능하면 모델 밖 실행 도구로 처리하고, 상위 지침이 요구하는 소통 주기를 지키면서 의미 있는 단계 변화·완료·오류 중심으로 알린다. 고정밀 진행률이나 비용을 추정해 단정하지 않는다.

## 실제 생성 이후 확인

사용자가 생성까지 요청한 경우에만 실행하고, 한 번 요청한 작업 ID를 추적해 중복 생성을 피한다. UI 시연을 요청하면 보이는 화면에서 입력·검증·Generate 클릭으로 진행하고 API 호출로 대신하지 않는다. 사용자에게 결과 화면을 남기고, 다운로드한 음악과 확정 가사·스타일·설정·실제 시드를 곡별 폴더에 보관한다. 기존 시도는 덮어쓰지 않거나 버전을 구분한다.

생성 완료 표시와 파일 존재·형식·길이를 확인한다. 내장 브라우저에서 다운로드 버튼을 눌렀어도 실제 파일이 저장됐는지 확인한다. 저장이 안 되면 무작정 반복 클릭하거나 재생성하지 않는다. API를 금지한 요청이 아니라 UI 입력·생성 시연 요청이었다면, 상황을 알리고 기존 작업의 결과만 로컬 결과 다운로드 API로 받아 보관할 수 있다. 사용자가 API 전체를 금지했다면 UI 저장 방법만 사용하거나 구체적인 막힘을 알린다. 시간 제한으로 토큰 생성이 잘렸다면 로그상 사실을 기록하고 마지막 가사와 종결이 자연스러운지는 별도로 청취해야 한다고 구분한다. 사용자 동의 없이 길이를 늘려 다시 생성하지 않는다. 새 가사 작성과 참고 음원 미사용은 표절 검사 완료를 뜻하지 않는다. 실제로 듣거나 비교하지 않은 발음·편곡·독창성을 검증했다고 주장하지 않는다.

2026-09-24에 다음 프로젝트 문서 및 예제를 확인했다.

- https://github.com/ServeurpersoCom/yue2.cpp/blob/master/docs/ARCHITECTURE.md — `style`은 쉼표 구분 태그, `lyrics`는 구조 태그 포함 가사이며 두 필드는 그대로 전달된다. 둘 다 비어 있으면 요청이 거절된다.

기본 프롬프트를 쓸 때마다 웹 조사할 필요는 없다. 사용자의 입력 화면이 다르거나 추가 설정·커버·악보 기능을 요청하면 해당 설치본이나 최신 프로젝트 문서를 먼저 확인한다. Suno나 이전 YuE의 규칙을 yue2.cpp의 규칙으로 대신 적용하지 않는다.
